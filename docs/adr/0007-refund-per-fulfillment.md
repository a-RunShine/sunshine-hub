# 退款按履约单走，运费不退，虚拟商品不接自助申请

退款的作用对象是 Fulfillment，不是 Order。混合订单里虚拟那张已经完成、不可退，实体那张才能退。按整单退会逼着处理"钱退了但皮肤已经穿出去了"这种情况。

用户能自助申请的范围只到实体履约单。虚拟道具支付即完成，不接申请。但 `SYSTEM_AUTO` 类型的退款必须保留：关单赢了支付回调时钱已经收了，那是系统的错，得原路退回，跟用户没有关系。

运费不退。退货时只退商品金额。运费是已经发生的成本，真实电商都这么做。

## Considered Options

- **按订单整单退**：金额和状态都简单，但混合订单里会把不可退的虚拟商品一起卷进来。
- **虚拟道具也接受自助退款**：对用户最友好，但要把皮肤从道具库里收回来，还得处理"已经装备过"这种没法判定的情况。

## Consequences

部分退款时订单状态保持 `PAID`，退款的事实记在 `t_refund` 上；只有全额退款才把订单转成 `REFUNDED`。这意味着订单和退款是两套独立的幂等骨架，`trade_no` 和 `refund_no` 各管各的，不能混用。

退款回调沿用支付回调那套幂等结构，参数换成 `refund_no`。两条回调对称，是这块唯一值得讲的地方。
