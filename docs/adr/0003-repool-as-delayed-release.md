# 回流放在同一场次里延迟释放，不另开场次

超时关掉的订单，配额不立刻回到可售池，先压在 Pending Repool 状态里，延迟 30 分钟再放回同一场次。

为什么不能立刻回：黄牛锁一单、不付款、盯着库存回升，就能零成本读出真实剩余量。这是这套系统最容易被钻的地方。

为什么不开独立回流场次：那需要一套完整的配额转移模型和开售编排，多出来的工作量换到的只是故事好听一点。延迟释放已经足够支撑反探测的论点。

## Consequences

回流释放和超时关单共用 RocketMQ 的延迟消息通道。这是有意为之的，让延迟队列在两个业务链路上都跑一遍，而不是只在关单时出现一次。

待回流的配额在延迟窗口内对用户不可见，页面上的"剩余份数"不包含这部分。这意味着"售罄"是可能被撤回的状态，前端不能把它画成终态。
