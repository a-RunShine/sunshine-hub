# 商品和售卖方式拆成两层

商品（Product 与 Sku）只描述它是什么，售卖活动（Campaign）描述这一次怎么卖。三种售卖方式不是三种商品，是三份 Campaign 配置。

不拆的话代码会长成这样：`if 限量… else if 普通… else if 折扣…`，每加一种售卖方式就要改这个分支，而且分支会从 service 层一路蔓延到 controller 和前端。

## Considered Options

- **按商品类型分表**：限量商品一张表、普通商品一张表。查询简单，但"我的藏品"要 union 三张表，下单流程要写三遍。
- **一张商品表加 type 字段**：改动最少，但每一层业务逻辑都要判 type。

## Consequences

同一件商品可以先后参加多场 Campaign：首发抢购、回流场、后来的折扣。这是拆开之后白拿的能力，不拆就实现不了。

库存因此有两个来源：普通售卖读 Sku 的 stock，限时抢购读 Allocation。两条路径并存是有意的，它们分别用数据库乐观锁和 Redis Lua 实现，正好构成一组可以对比着讲的取舍。
