# 订单管钱，履约单管货

一次结账生成一个 Order，Order 按商品形态拆成多个 Fulfillment。虚拟履约单在支付成功时立即完成，实体履约单进入待发货。

一个订单里同时有皮肤和手办时，单个状态字段表达不了"皮肤到账了、手办还没发"。硬要表达就会衍生出"部分完成"这种谁也不敢用的含混状态。

## Considered Options

- **虚拟和实体各下一单**：履约天然独立，但用户买两样东西要付两次款。
- **不拆履约，只记一个发货状态**：最省事，但混合单的发货状态必然失真。

## Consequences

退款按履约单粒度处理。虚拟履约单一旦完成不可退，皮肤进了道具库就没有回收机制，硬要退就得处理"用户已经把皮肤穿出去了"这种情况。

这也是支付回调与超时关单的竞争必须显式处理的原因。关单赢了而钱已经收了时，订单是 `CLOSED`，履约从未发生，退的是整笔钱，不涉及退货，因为货还没出去。真正需要退货的退款，发生在履约完成之后，那才需要按履约单一张张算。
