# 抢占成功时就绑定收藏编号

编号在用户抢占成功、订单创建的那一刻绑定，不等支付完成。用户点完就要看到自己是几号，这是收藏品的产品逻辑。

代价是扣配额、查限购、取编号三件事得塞进同一个 Lua 脚本，任何一步失败都要整体回退。

未支付的订单关闭后，编号作废，不回收。编号一旦展示出去就是公开信息，回收重发会出现两个用户拿着同一张截图。

## Considered Options

- **支付成功后再分配**：Lua 脚本只需要管配额和限购两件事，编号分配还能复用支付回调的幂等逻辑。否掉的原因是用户付钱之前不知道自己买的是几号，收藏品的体验就没了。
- **支付后抽号**：可以做成"拼手气"的玩法，但要多一层待抽号状态，对本项目没有额外价值。

## Consequences

编号池和配额池必须同步。配额扣成功了但编号池是空的，整个操作失败并抛出可识别的业务异常。不允许出现"扣了配额却没拿到号"的中间状态。
