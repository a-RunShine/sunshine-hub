# 限时抢购前端统一服务端校时、在途防重与可恢复态轮询

限时抢购页面的时序判定、防重复提交、可恢复态刷新与收藏编号展示遵循以下机制契约：

1. **统一服务端时钟偏移校准**：每次成功拉取场次详情（`GET /campaigns/{campaignId}`）或抢购成功（`POST /campaigns/{campaignId}/claim`）时，均用响应携带的 `serverTime` 与当前本机时刻计算服务端时钟偏移量（`serverTime` 解析失败时偏移量回落为 `0`，避免 `NaN` 污染计算）。页面所有时序比较与倒计时——开售倒计时（`startAt`）、结束倒计时（`endAt`）、冷却剩余倒计时（`cooldownUntil`）、开售后隐藏预约入口的判定以及成功后的付款截止倒计时（`payDeadline`）——统一基于校准后的服务端口径时刻计算，不直接信任本机时钟；详情请求层同时按单调序列丢弃乱序返回的过期响应，确保旧响应不覆盖新状态。
2. **同步引用标记（ref）作为真实防重闸口**：抢购提交控制器在同步入口处以内存 ref 标记阻断在途重复触发（请求未归前再次触发直接忽略，并在请求结束及切换场次时复位）。按钮 `disabled` 仅是表层反馈，不充当并发防重依据；提交状态限定为页面内瞬时状态，不进全局 store，刷新页面即重置。
3. **仅对可自动恢复态开启可见性感知轮询**：页面仅在场次详情处于可自动恢复不可点状态（配额售罄 `available === 0` 或存在未到期的 `cooldownUntil`）或抢购提交失败处于可恢复错误码（`SOLD_OUT` / `PURCHASE_COOLDOWN`）时，启动 `15` 秒周期定时重拉。页面切到后台不可见时暂停计时器，切回前台时立即补拉一轮再继续计时；不可恢复态不挂常驻定时器，也不监听页面可见性变化。
4. **恢复解除绑定失败后的新详情轮次**：详情数据层为每次成功响应维持单向递增的加载轮次；当提交进入可恢复失败态时记录当前轮次，只有后续到达的新详情轮次严格大于失败时刻轮次、且新详情口径判定为可购时，才清除失败状态回到可点，避免失败前拿到的旧详情提前抹掉刚返回的 `SOLD_OUT` 或 `PURCHASE_COOLDOWN` 失败提示。
5. **收藏编号原样保留字符串展示**：抢购成功结果面板按契约字符串原样渲染 `ClaimResult.collectibleNumber`（如 `0427`），不做数值解析或前导零裁剪。

## 与既有 ADR 的关系

- **[ADR-0001](0001-claim-binds-collectible-number.md)**：抢占成功即绑定并展示收藏编号，要求前端原样保留字符串前导零，并按响应 `serverTime` 校准付款截止倒计时。
- **[ADR-0003](0003-repool-as-delayed-release.md)**：待回流配额延迟 30 分钟释放且共享缓存允许约 2 秒滞后，「售罄」不是终态。本 ADR 的可恢复态可见性轮询与新详情轮次解除屏障，既避免把售罄画成终态，也防止滞后旧详情误消除刚返回的 `SOLD_OUT` 失败态。
- **[ADR-0009](0009-real-name-at-purchase.md)**：未登录（`401`）与未实名（`403 REAL_NAME_REQUIRED`）不落入失败提示，而是复位为空闲态并触发登录回跳或实名表单；提交实名后的自动重放仍走同一抢购入口与在途防重闸口。
- **[ADR-0013](0013-two-tier-cooldown.md)**：购买冷却到期自动恢复，与售罄回流复用同一套可恢复态轮询、服务端校时冷却倒计时与新详情轮次解除屏障。

## Considered Options

- **直接读取本机 `Date.now()` 做倒计时与开售判断**：本机时钟被拨快或存在偏差时，会出现预约入口提前消失、未开售或冷却倒计时失准。
- **仅靠按钮 `disabled` 防连点**：React 状态更新跨渲染帧异步生效，同帧双击或实名重放回调仍可能并发发出多个抢购请求。
- **所有失败态常驻短轮询，或引入 WebSocket / SSE 推送**：对已结束、本场额度用尽等终态轮询纯属无效流量；为延迟 30 分钟的回流与定时冷却另建推送长连接基础设施则超出当前复杂度收益比。
- **不校验详情轮次，详情一可点就清失败态**：缓存滞后或请求竞态下，抢购前拿到的详情可能仍显示可点，导致刚失败的 `SOLD_OUT` / `PURCHASE_COOLDOWN` 提示瞬间被旧快照冲掉。
- **把 `collectibleNumber` 转成整数存储或格式化**：会丢掉固定位宽前导零，破坏收藏编号展示语义。

## Consequences

- 限时抢购页新增任何基于当前时刻的展示或判定都必须经由服务端时钟偏移校准，不得直接消费裸 `Date.now()`；`serverTime` 异常时偏移量归零，优先保证页面不出现 `NaN` 倒计时。
- 配额回流或冷却到期后，若标签页持续停留且不刷新，页面恢复可点最多存在一个 `15s` 轮询周期的延迟（切回前台会立即补拉）。
- 恢复解除强依赖详情数据层的单调轮次递增契约与提交状态机生命周期，调整任一侧状态流转时必须同步核对「新详情轮次严格晚于失败时刻」这一不变量。
- **可逆性**：属于前端页面层状态机与轮询策略（双向门），但修改轮询条件、轮次解除屏障或同步防重闸口会影响缓存滞后容错与防重提交不变量，变更前需同步复核 ADR-0003 与 ADR-0009 对应测试。
