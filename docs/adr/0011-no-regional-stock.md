# 库存不按地域切分，需要削峰时用技术分片

库存是一个整池，不分成华东、华南、海外。

按地域切库存在电商里不存在。库存在全国是一个池子，分仓是物流层面的就近发货，不是售卖层面的准入。游戏道具更没有地域限制。

需要减轻单个 key 的压力时，正确做法是**库存分片**：把 5000 拆成若干个 500，键名带分片序号，请求按 hash 落片。这是纯实现细节，用户无感知，看到的仍然是「剩余 183 份」。

## Considered Options

- **按大区切分**：用户能看到「我在华东还剩多少」，但那是个虚构的业务概念，还得先选一个大区，凭空多一步操作和一个数据维度。
- **首版就分片**：提前上复杂度，而 5000 份库存在一个 key 上跑 Lua 大约能到 5 到 10 万 QPS，本项目的峰值到不了。

## Consequences

`t_allocation` 一个场次只有一条记录，没有 `region` 字段。

Redis 键是 `alloc:stock:{campaignId}`，不带地域后缀。

如果压测证明单 key 是瓶颈，加的是分片序号而不是地域，前端不需要任何改动。这是分片和地域切分的关键区别：前者是实现细节，后者是业务概念。
