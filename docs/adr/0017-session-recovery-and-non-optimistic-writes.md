# 前端会话恢复区分 401 与网络故障，204 写操作不做乐观更新

前端启动时的会话恢复、受保护入口的鉴权跳转分流以及 `204` / 会话变更类写操作遵循三项机制边界：

1. **会话恢复区分 `401` 与故障**：应用启动时请求 `GET /me`（按请求关闭全局响应拦截器的自动跳登录策略），以四态认证生命周期（未初始化 / 恢复中 / 已确认 / 故障）追踪会话恢复进度，并在处于恢复中或已确认状态时跳过重复探测（兼容开发期重复挂载）。只有服务端明确返回 **`401`** 时才确认当前为「已确认未登录态」（认证账号为空且生命周期进入已确认态）；遇到 **`5xx`、超时或网络异常** 时转入故障态，由路由鉴权守卫展示带重试入口的故障界面，不把状态未明的访问者按匿名踢回登录页。全局认证 store 仅持有客户端登录态，不缓存服务端业务数据。
2. **`POST /campaigns/{campaignId}/claim` 的 `401` 交由页面层回跳**：全局响应拦截器默认在 `401` 时执行整页跳转前往 `/login?next=...`；抢购提交请求显式关闭该全局抢跳，捕获 `401`（`UNAUTHORIZED`）后先把页面提交状态复位回空闲态（`idle`，不在按钮区滞留错误文案），再交由页面层经 React Router 触发 SPA 跳转，使会话过期抢购、匿名点击预约/抢购与路由鉴权守卫共用同一套 `next` 回跳口径。
3. **`204` 与会话变更写操作不做乐观更新**：`POST /campaigns/{campaignId}/reserve`、`DELETE /campaigns/{campaignId}/reserve` 与 `POST /auth/logout` 均返回 `204` 空体。客户端不解析响应体，也不在请求完成前乐观改写本地状态：预约与取消预约在写操作在途期间禁止重复提交，等待 `204` 返回后再重新拉取场次详情以服务端最新 `reserved` 为准（失败时仅呈现错误提示）；登出同样在请求在途期间禁止重复提交，等待 `POST /auth/logout` 成功返回后再将全局认证账号置空（`null`）并置回已确认态（即已确认未登录态，而非退回未初始化态，避免路由鉴权守卫卡在加载态）；`PUT /me/real-name` 同样在 `200` 返回最新 `Me` 后再回写认证账号并重放抢购。

## 与既有 ADR 的关系

- **[ADR-0008](0008-session-over-jwt.md)**：系统用 Redis 存 Session 并以 HttpOnly Cookie 承载会话凭证。前端脚本无法直接检查 Cookie 有效期，因此启动必须请求 `GET /me`；同理，登出必须等待服务端删除 Redis 会话并返回 `204` 后再将本地认证状态切至已确认未登录态，否则服务端会话仍存活，页面刷新后会重新进入已登录态。
- **[ADR-0009](0009-real-name-at-purchase.md)**：允许未登录与未实名访问者浏览限时抢购页并在点击后拦截。`GET /me` 与 `POST /campaigns/{campaignId}/claim` 显式关闭全局自动跳登录，避免公开页面启动探测 `GET /me` 吃 `401` 被全局拦截器跳走，也让抢购 `401` 在复位页面提交状态后走统一 SPA 回跳。

## Considered Options

- **启动 `GET /me` 任何失败（含 `5xx` 与断网）一律置为已确认未登录态**：后端抖动或短暂断网时，停留在受保护页的已登录访问者会被直接重定向到 `/login`，体验割裂且回跳后仍可能重复失败。
- **所有 `401` 统一在全局拦截器里执行整页跳转**：公开页面挂载探测 `GET /me` 会被直接跳去登录；抢购 `401` 也会绕过组件内空闲态复位而触发整页刷新。
- **对预约、取消预约或登出先做乐观 UI 更新，失败再回滚**：在网络失败或服务端拒绝时，界面会短暂甚至持续展示与服务端不一致的预约态或已登出假象；尤其登出失败却清空本地登录态，会在刷新页面后「重新登录回来」。

## Consequences

- 凡允许匿名访问的探测接口或需由页面层控制跳转时机的请求，调用时必须显式关闭全局拦截器的自动跳登录；未关闭的受保护接口继续依赖全局拦截器处理 `401`。
- 路由鉴权守卫在会话恢复处于故障态时必须阻断受保护页渲染并提供重试入口，不得降级为匿名放行或登录跳转；登出成功后必须落在已确认未登录态，不得退回未初始化态。
- 非乐观写操作会在请求在途期间禁用触发按钮，并在预约成功多承担一次详情重拉往返，换取界面状态与服务端真相一致。
- **可逆性**：属于前端会话状态机与请求拦截边界约定（双向门）。后续若出现局部草稿类低风险写操作可单独评估乐观更新，但身份会话、预约与交易写入应维持服务端确认后再更新的边界。
